 === DTLS LAYER ===
  - DTLS 1.2 server on UDP 24083
  - Standard 6-flight handshake: ClientHello -> HelloVerifyRequest(cookie) -> ClientHello+cookie -> ServerHello+Cert+SKE+Done -> CKE+CCS+Finished ->
  ServerCCS+Finished

  === GRIDMATE CARRIER (over DTLS Application Data) ===
  Datagram framing:
    [prefix:u16BE] [dgramSeq:u16BE] [message1] [message2?] ...
  - Prefix: 0x8001 uncompressed, 0x8101 LZ4 body
  - S->C we use 0x8001 for everything; dgramSeq starts at 2

  Message header flag bits:
    0x01 MF_RELIABLE          requires ACK; relSeq present
    0x04 MF_CHUNKS            chunks-countdown u16BE present
    0x08 MF_SEQUENTIAL_ID     seq implied prev+1
    0x10 MF_SEQUENTIAL_REL_ID relSeq implied prev+1
    0x20 MF_DATA_CHANNEL      channel u8 follows
    0x80 MF_CONNECTING        handshake-phase

  Our SM_CONNECT_ACK (test-39 format; 0x21/relSeq=0 like real server instant-disconnects our path):
    [0x8001][dgramSeq]
      MSG1: flags=0xa0 ds=5 ch=3 seq:u16 relSeq=0xffff   payload=[u32BE version][SM_CONNECT_ACK=0x02]
      MSG2: flags=0x88 ds=6           relSeq=0xffff      payload=[ackPayload]

  Standalone keepalive ACK (ch=3):
    flags=0x20 ds ch=3 seq relSeq=0  [0x40][lastDgramSeq:u16BE][firstDgramSeq:u16BE][SM_CT_ACKS=0x06]

  Per-channel independent seq + relSeq counters (ch0/ch1/ch3/ch4).

  === NW PROTOCOL WRAPPER (inside ch0/ch1 carrier payloads) ===
    [PackedSize_LE(innerLen)] [0x00] [0x01] [type:u8] [data...]
  PackedSize_LE = LE VLQ (0xxxxxxx=1B, 10xxxxxx=2B, ...). 0x00 0x01 marker is constant.

  === KEY WIRE-FORMAT GOTCHAS WE HIT ===
  - NO "post-connect extra byte" in carrier messages. Adding any byte after [ch:u8] shifts NW payload by 1 -> "server data error" disconnect.
  - flags=0x88 (MF_CONNECTING|MF_SEQUENTIAL_ID) does NOT set MF_SEQUENTIAL_REL_ID, so relSeq MUST be written. Missing -> BAD_PACKETS.
  - Real-server SM_CONNECT_ACK shape (0x21/relSeq=0) instant-disconnects on our path; only the test-39 form above (0xa0/relSeq=0xffff) works.
  - 0xa3 WorldSpawn map path must be exact "coatlicue/NewWorld_VitaeEterna"; truncation -> infinite loading circle.
  - 0x8001 prefix is safe S->C (real server uses 0x8101 LZ4 for ~59%, but uncompressed works fine).
  - CH1 unit[0] (~47KB init burst) is mandatory -- without it client freezes at loading circle. NW_HYBRID_INIT bisection: 67 -> loading, 68 -> black screen
  (game world).

  === C->S AFTER HANDSHAKE ===
  LZ4-compressed 0x8101 datagrams:
    [crc32:4B][size:4B][session:8B][peer:8B][0x0001:2B][type:1B][data...]
    Inner: [prefix:1B][entity_hash:8B][session_id:8B][...]

  Server echoes entity_hash + session_id in template responses (14 type mappings).
  Fire-and-forget C->S types: 0x82 0x83 0x9a 0x9d 0x94 0xa6 0xb0 0xb4 0xb9 0xbd 0xbf
