## What we're doing

Building a private server emulator for New World (Amazon's MMO) because Amazon has announced shutdown for the live service around Dec 2026. The server must accept the real client binary, pass auth, and let the player enter a static world. No combat/NPCs/persistence required for MVP.

The work has four gates:
1. **Gate 1 — Auth flow.** Done. Mock HTTPS server at `server/auth_mock.py` handles the full OmniSDK → credentials → entitlements → character-create → name-reservation HTTPS flow.
2. **Gate 2 — Javelin REP (DTLS over UDP).** In progress. This is what we're working on *right now.*
3. **Gate 3 — World streaming.** Not yet.
4. **Gate 4 — Input/movement.** Not yet.

## What we accomplished today (2026-04-23)

Broke through the **DTLS trust gate** on the archived non-EAC build. The client now completes a full DTLS 1.2 handshake against our self-signed cert and sends encrypted application data.

Key sub-findings:
- `FUN_145dce750` (`Javelin_SecureSocketDriver_Initialize`) has two branches:
  - **Permissive** (when `ctx+0x288` is null): registers always-accept callback `FUN_1402a1a70` (returns 1).
  - **Strict** (when `ctx+0x288` is non-null): loads the embedded CA bundle and does normal OpenSSL validation, which rejects our self-signed cert with `unknown ca`.
- The **working bypass** is a Frida `Interceptor.attach` on `FUN_145dce750` that nulls `ctx+0x288` **before** the function body runs. The function's own `JZ` at `0x145dce8b5` then naturally takes the permissive branch. SSL_CTX ends up cleanly configured.
- An earlier **byte patch** that rewrote `JZ → JMP` at `0x145dce8b5` failed — it forced the permissive branch but left the SSL_CTX half-wired (strict branch's CA-list setup was skipped), and the client created the UDP socket but never sent a ClientHello before CTD'ing ~2.68s later. Data-level bypass is the right approach.
- The REP state machine transitioned **state 9 → state 10** for the first time today. That's post-secure-init, waiting for server-sent Javelin messages.

## Where we are right now — the exact next thing

### The situation

1. Frida trust bypass works. Probe got a full handshake at 15:16 session (`capture/dtls_probe_20260423_151655.log`).
2. That probe log **captured one encrypted application-data record** at line 405 (`17 fe fd 00 01 00 00 00 00 00 01 00 3b` + 59 bytes of ciphertext) — the client's first Javelin message — but **openssl was shutting down the connection right after the handshake completed**, so the bytes were never decrypted.
3. Root cause: `openssl s_server -dtls1_2 -quiet` with `stdin=DEVNULL` tears the connection down the instant stdin hits EOF.
4. I tried two fixes in this session: (a) `stdin=subprocess.PIPE` — broke the probe entirely because `s_server` on Windows hangs on blocking pipe reads and starves the UDP loop; (b) `-rev` flag — rejected by openssl ("Can't use -rev with DTLS").
5. **Current fix in place (not yet tested):** reverted to `stdin=subprocess.DEVNULL` + added `-ign_eof` flag. `-ign_eof` explicitly tells `s_server` to not shut down on stdin EOF and does work with DTLS.

### What to do first

Run the three-terminal flow **with the current probe as-is** and see whether we finally capture decrypted plaintext:

```powershell
# Admin PowerShell 1 — auth mock
python -m server.auth_mock --port 443

# Admin PowerShell 2 — DTLS probe (openssl s_server wrapper)
python tools\dtls_probe.py

# Admin PowerShell 3 — spawn archived build with Frida trust bypass + hooks
python tools\frida_capture.py --exe "<archive-game-exe>" --name archived_probe_running
```

Play to character creation → click "enter world" → let it run 15–20 seconds. Then Ctrl-C the probe.

**Look in the probe log** (latest in `capture/dtls_probe_<timestamp>.log`) for:
- `SSL_accept:SSLv3/TLS write finished` — handshake done
- **No** `ERROR` / `close notify` / `CONNECTION CLOSED` immediately after (that's the fix confirmation)
- Raw application-data hex blocks after `write finished` — those are the **decrypted** first Javelin records

If you get decrypted bytes, feed them to `server/javelin/frame.py` (has `parse_datagram()`, MessageFlags, SystemMessageId enums; 14/14 round-trip tests passing). That identifies the message type and fields.

### What to do after the first decrypted record

Start building `server/rep_responder.py` — a real DTLS+Javelin server to replace `s_server`. Minimum viable behavior:
1. Terminate DTLS using the same `server/certs/server.crt` / `server.key`.
2. Parse incoming Javelin records via `server/javelin/frame.py`.
3. Send back the auth/welcome message the client's `FUN_146b6f190` expects. Per prior RE notes, that handler sets `repObj+0x601 = 1` when it sees a type-ID matching `FUN_1407f2e80()` with `msg[+0x8] == 0`. Without this message the client stalls forever at state 10.

## Key RVAs / addresses (archived binary, base `0x140000000`)

- `FUN_145dce750` (`Javelin_SecureSocketDriver_Initialize`) — DTLS driver init, contains the trust-mode branch. RVA `0x5dce750`.
- `0x145dce8b5` — the JZ inside `FUN_145dce750` that picks permissive vs strict. DO NOT byte-patch; hook the entry and null the input field instead.
- `FUN_1402a1a70` — always-return-1 verify callback used by the permissive branch.
- `ctx+0x288` (= `param_1[0x51]` in decompile) — the `verifyField` / CA-bundle slot. Nulling this before function entry forces the permissive branch.
- `ctx+0x270` — `modeField` (U8). Currently 0 in all observations; not the switch we care about.
- `0x149f80d90` — embedded PEM bytes for the real `CN=New World` server cert. Unused by us; referenced for future cert-pinning analysis if needed.
- `FUN_14644a070` — REP state machine tick, handles state 9 → 10 transition.
- `FUN_14646d460` — REP wrapper tick (state 9 and 10 entries, queue drain at `wrapper+0x118`).
- `FUN_146b6f190` — server-to-client message handler. Sets `repObj+0x601 = 1` on successful auth message. This is the ready-flag we need the server to trigger.
- `FUN_1407f2e80` — returns the type ID the above handler matches against.
- `Javelin_BitStream_ReadBits @ 0x140f7c420` — reference for `server/javelin/bitstream.py`.

## Environment gotchas

- Windows UTF-8: set `PYTHONIOENCODING=utf-8` for subprocesses; never put unicode chars in `print()`.
- Frida APIs: modern form only — `ptr.readByteArray(len)` not `Memory.readByteArray(ptr, len)` (removed in Frida 14+).
- Ghidra MCP bridge: may be offline. When offline, don't try `mcp__ghidra__*` calls — ask user to start Ghidra or route the query through Codex via a pasted prompt.
- `git add -A` is banned — `capture/` dirs are huge. Always stage specific paths.
